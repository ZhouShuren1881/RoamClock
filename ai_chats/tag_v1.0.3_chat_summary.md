## 002 分析并移除 adapter-cache 冗余

### 用户要求

1. 分析创建 adapter-cache 的原因及其是否必要，此阶段先不进行修复。

2. 随后移除冗余实现，并自行测试 adapter。

### Agent 任务规划

先只读分析缓存创建、历史用途及卸载清理机制。用户随后授权移除冗余，改为直接加载原始 DLL，由原生端自行计算内容哈希以保留通道隔离，解除通道对缓存目录名的依赖；清理相关配置、测试和文档，并验证协议及真实桌面的生命周期行为。

### 最终完成情况

初步分析指出，缓存副本原用于避免 Explorer 驻留模块锁住发布 DLL，并以父目录哈希标识不同版本的通信通道；后来移除永久驻留并迁移缓存位置后，复制逻辑仍被保留，且没有自动清理旧缓存。

已移除缓存目录创建与 DLL 复制逻辑，直接加载 `RoamClock.Native.dll`。原生端自行计算内容哈希，仍按 Explorer PID 与 DLL 内容隔离通道；同步更新构建配置、忽略规则、测试引用及两份 README。项目内旧缓存已清理，测试期间没有重新生成；集成测试新增确认 Explorer 加载指定原始 DLL 的断言。

记录中的验证全部通过：

- 原生协议字段、Unicode、所有权与释放。
- Debug 与 Release 原生 DLL 的桌面接入、内容和天气图标更新、停用及恢复。
- 正常退出与测试控制进程被强制结束后的原生内容清理、DLL 卸载及文件解锁。
- 崩溃后新控制进程重新接入；测试期间 Explorer 进程保持不变。
- 主项目 Release 构建为 0 警告、0 错误。

首次桌面测试因受限环境无法发现任务栏而超时，切换到当前用户桌面后通过。测试结束已恢复原安装版本后台运行。直接加载后，运行期间原始 DLL 会被占用，替换或重新构建前需要退出程序；恢复运行的原安装版本并不包含本次修改。

### 用户要求

### 最终完成情况

已移除天气缓存文件读写、城市哈希缓存路径及缓存目录配置。每次运行重新获取天气，仅保存在内存变量中；请求失败时保留本次运行中同城市最近成功的数据，重新启动不会恢复上次运行的数据。城市切换清空旧快照，并继续防止旧城市请求覆盖当前状态。

同步移除 Style Check 的缓存路径提示，将过期缓存示例和悬停标记改为过期天气表述，更新 README 与测试。测试覆盖每次新建服务重新获取、离线重启无旧数据、内存快照保留、手动刷新、城市竞态、超时重试、取消请求，以及天气服务不创建文件或目录。

天气相关 13 项检查先通过，完整测试随后发现已有 UTC 偏移负号断言与当前界面不匹配；同步将该断言及无天气占位符断言改为当前使用的 `-` 与 `--` 后，完整 24 项离线检查全部通过，差异格式检查通过。对话未记录真实天气网络或桌面交互验证。
